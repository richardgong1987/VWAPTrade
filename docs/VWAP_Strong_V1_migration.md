# VWAP Strong V1 — 参数迁移说明

对应 `docs/VWAP_Strong_V1.pdf`。本文只讲**从旧版升级时必须手工处理的事**。

## 1. 参数改名：`VwapSlopeMin` → `VwapSlopeRateMin`

这是本次唯一的破坏性参数变更，**不会自动迁移**。

| | 旧 | 新 |
| --- | --- | --- |
| C# 属性名 | `VwapSlopeMin` | `VwapSlopeRateMin` |
| 比较的量 | `SlopeRawX`（原始斜率） | `SlopeRateX30 = SlopeRawX × 6/N`（30 分钟标准化速度） |
| UI 标签 | VWAP斜率最小值 | VWAP斜率速度最小值 (30分钟标准化) |

改名是**故意的**：两个量纲不同，同名会让旧阈值被静默当成新阈值用。

**换算**：只有在 N 和 ATR 口径都不变时，旧阈值才有数学上对应的新阈值：

```
新阈值 = 旧阈值 × 6 / N
```

例：旧 `VwapSlopeMin = 0.30`、旧 N = 12 → 新 `VwapSlopeRateMin = 0.30 × 6/12 = 0.15`。

**不知道当时的 N 就不能换算** —— 老 CSV 没有记录 N（`LookbackN` 列是本版才加的）。这种情况只能重新标定，不要猜。

### 需要人工处理的地方

- **cTrader 界面上保存的参数集 / `.cbotset` 文件**：旧的 `VwapSlopeMin` 不会被识别，该参数会回落到默认值 `0`（即斜率过滤关闭）。升级后请逐个检查并重填。
- **批量回测后端**：`scripts/run_conditions.py` 按 C# 属性名下发参数。后端参数库里所有 `VwapSlopeMin` 记录都要改成 `VwapSlopeRateMin` 并按上式换算数值。**这一项在本仓库之外，属于待办**；在改完之前，那些记录跑出来的是「斜率过滤关闭」的结果。

## 2. 默认值变更

| 参数 | 旧默认 | 新默认 |
| --- | --- | --- |
| 止损偏移点数 `StopOffsetTicks` | 400 | 50 |
| 保护止损触发R `BreakevenTriggerR` | 1.0 | 0（关闭） |
| 斜率回看K线数 `VwapSlopeLookbackBars` | 12 | 6（= 30 分钟） |
| 启动时清空交易记录CSV `ResetTradeLogOnStart` | false | true |

风险 1%、止盈 2R、保护止损偏移 50、debug false 保持不变。

**保护止损默认改成 0 意味着保本止损默认不再启用**；其算法本身没有改动，需要时把触发 R 调回正数即可。

## 3. 未由 PDF 指定、本次沿用现状的假设

- **`ATR归一周期` 默认仍是 `ATR14_H1`**。PDF 第 4 节说明「当前更倾向 M5，但仍处于研究阶段」，没有指定唯一默认项。保持 H1 是为了让升级前后的默认行为一致，A/B 时再显式切换。枚举名与取值未变。

## 4. 只支持 M5

`SlopeRateX30` 的 `6/N` 系数写死了「M5 上 6 根 = 30 分钟」。挂到其他周期上这个系数不成立，因此 `OnStart` 会检查周期，非 M5 直接报错并停止，不会按错误系数静默计算。`N < 1` 同样拦下。

## 5. CSV

列数 31 → 43，新列全部追加在末尾，旧列的顺序和含义不变：

- `ATR14`、`GapX` = **所选周期**那一套的读数
- `SlopeX` = **原始斜率**（未做 30 分钟归一），新的速度值在 `SlopeRateX30_*` 列

旧文件由 `TradeCsvMigrator` 自动补空列升级，数据不丢。老记录的 `LookbackN`、`ATR14_M5` 等新列留空 —— 当时的 N 和 ATR 周期无从得知，不能伪造。

## 6. 已知的时间对齐特性（本次不改）

`Atr14Series` 取的是「信号 K 线所在那一根的前一根」ATR，以确保绝不用到未走完的数据。选 `ATR14_M5` 时，这意味着 ATR 相对信号 K 线**滞后一根（5 分钟）**。ATR14 是 14 根的均值，一根的滞后对归一没有实质影响。本次按要求保留现有取值时刻，未调整对齐算法。
